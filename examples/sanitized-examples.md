# 脱敏示例

以下内容来自真实使用记录，**已移除所有可识别信息**：

- 用户名 → `<user>`
- 机器具体型号 → 通用描述
- 外设型号 → 通用描述
- 路径中的用户名 → `<user>`

**这些示例的用途**：让你看到真实记录长什么样，以及「现象与根因隔得很远」的坑是怎么记的。

---

## 示例一：一个典型的 log 条目

```markdown
## 01:38  修复应用启动崩溃（配置文件带 UTF-8 BOM）

- **智能体**：Claude-sonnet-4.5-a1b2c3d4
- **操作**：剥离 `~/.config/app/package.json` 文件头 3 字节 BOM（`EF BB BF`），
  重排为 2 空格缩进、UTF-8 无 BOM、LF 换行。备份 `package.json.bom-bak-20261122-013825`
- **原因**：应用启动即崩。崩溃日志显示
  `SyntaxError: Unexpected token '﻿', "﻿{" is not valid JSON at readProfileManifest`
  `JSON.parse` 不剥离 BOM，配置文件读不了 → 主进程启动失败。17:36–17:37 连崩 4 次
- **源头**：文件内容形如 `"name":  "profile-name"`（双空格缩进），是 PowerShell 5.1
  的 `ConvertTo-Json` + `Out-File` 特征写法，而 `-Encoding utf8` 默认**写 BOM**
- **影响**：仅该配置文件。语义未变——去 BOM 前后 JSON 等价
- **验证**：`~/.config` 下 27 个 JSON 全部通过解析
- **回滚**：`cp package.json.bom-bak-20261122-013825 package.json`
- **教训**：往 JSON/YAML 写内容别用 PS 5.1 的 `Out-File -Encoding utf8`（会带 BOM），
  改用 Python 或 `[IO.File]::WriteAllText`
```

**这个条目的价值**：
- 「教训」一行是三个月后最有用的部分
- 「源头」解释了为什么会发生（某个工具的默认行为），下次能预防
- 「验证」说明改动是安全的

## 示例二：坑点备忘（OUTLINE 第 N 节）

这是投入产出比最高的一节：**现象和根因隔得很远的坑**。

| 现象 | 真相 |
|---|---|
| 删了文件后磁盘空间没释放 | 某些工具的 safe-delete 会把文件放进回收站中转目录，必须清回收站 |
| `Remove-Item -Recurse` 报某个方法不存在 | PowerShell 5.1 的已知 bug，删目录改用 `[System.IO.Directory]::Delete($p,$true)` |
| `powershell -File D:\x.ps1` 报路径不存在 | 当前 shell 吃了反斜杠，用正斜杠 `D:/x.ps1` |
| 改注册表路径变成正斜杠 | 命令文本传输会把 `\` 转 `/`，用 `os.path.normpath()` 兜底 |
| 后台进程跑一会儿就没了 | `&` 启动的子进程随终端会话结束被杀，改用 WMI `Win32_Process.Create` |
| 加密卷上的目录「变空了」 | BitLocker 自动解锁失败，重启一次即可（不是数据丢失） |

**注意每一条的形式**：左边是**你看到的**，右边是**真正的**。这个格式很关键——下次你搜「磁盘空间」能搜到，搜「回收站」也能搜到。

## 示例三：一个完整的主题条目（OUTLINE 的一节）

```markdown
## 6. 显示

**核心问题**：外接屏经 USB-C→HDMI 转接，锁屏唤醒后偶发掉分辨率/刷新率。

**根因链（三级降级）**

| 级别 | 触发 | 显示器报的 EDID | 可用模式 |
|---|---|---|---|
| 正常 | 链路稳定 | `VENDOR-A` v1.4 | 106 种，最高 120Hz |
| 降级 | 转接器降速 | `VENDOR-B` v1.3 | 只到 100Hz |
| 失败 | 握手未成功 | 无（`DEFAULT_MONITOR`） | 9 种 VESA，1024×768 起 |

**已部署的兜底**
- 守护脚本常驻，每 2 秒检查，掉到低分辨率自动拉回
- 修复脚本按当前 EDID 实际支持的最高模式设置
- 软拔插脚本重启显卡设备强制重读 EDID —— **实测这是唯一有效的软件手段**

**已验证无效的**
- `pnputil /scan-devices` — 不重读 EDID
- 重启 `DEFAULT_MONITOR` 节点 — 它是空壳，没有 EDID 可读
- 重启显卡驱动快捷键 — 不触发重新枚举
- 往 `Device Parameters\EDID` 写数据 — 握手失败时根本不读缓存

**唯一根治**：换直连线（顺便能上更高刷新率）
```

**这个条目的结构值得学**：
1. **核心问题**一句话
2. **根因链**用表格（比文字描述清楚得多）
3. **已部署的方案**
4. **已验证无效的** ← 这一项最省时间，避免重复试
5. **根治方案**

## 示例四：一次排查过程的记录（log）

```markdown
## 03:32  找到多轮对话必空的真因：消息缺 source 字段

- **智能体**：Claude-sonnet-4.5-a1b2c3d4
- **操作**：在插件入口加 `withAssistantSource()`，给每条 assistant 消息补 source 字段
- **真因（三个 bug 叠加）**
  1. 宿主 `forAdapter` 对 `const source = message.source; if (source.replayState === void 0)`
     缺判空 → 外部消息无 source 字段时抛 TypeError
  2. 插件把异常吞成「正常空完成」→ 上层判定为可重试错误，空跑 7825ms 才报错
  3. 角色大小写不统一，非标准写法掉进兜底分支被当 user 消息
- **为什么只有多轮崩**：单轮没有 assistant 历史，代码在判空那行之前就短路了
- **修复**：
  ```js
  function withAssistantSource(message, channel, modelId) {
    if (message.role !== "assistant" || message.source !== void 0) return message;
    return { ...message, source: { kind: "model", provider: channel, model: modelId } };
  }
  ```
- **影响**：插件主文件 +2536 字节
- **验证**：单测 5/5；网关实测 4 通道多轮全部通过
- **回滚**：`Copy-Item index.js.orig index.js -Force`
- **跨仓库先例**：`amimi-wenke/dsh-room-world#1` 有逐字同一段代码的记录
```

**这条记录的价值**：
- 「真因（三个 bug 叠加）」把复杂问题拆清楚了
- 「为什么只有多轮崩」解释了边界条件
- 「跨仓库先例」证明这不是孤例

## 示例五：一次「错误的判断」也要记

```markdown
## 03:36  教训：「空响应」这个症状会伪装一切原因

- **背景**：本次排查耗时约 2 小时，连续 4 轮结论全错，全部被同一个症状误导
- **错误链条**

  | 轮次 | 结论 | 依据 | 实际 |
  |---|---|---|---|
  | 1 | 不是反反代 | 代码无功能门、注释意图相反 | 方向对，但根因错 |
  | 2 | 是反反代（上游指纹） | 大小写变体能跑通，像改词绕过 | 纯属巧合 |
  | 3 | 上游不支持某角色 | 其他角色通过 | 是宿主崩溃 |
  | 4 | 角色大小写 bug | 序列化层精确匹配 | 只是第三层因素 |

- **教训**
  1. `200 + 空 content + finish_reason:"stop"` 是所有故障的共同出口——
     上游拒绝、额度不足、模型下线、宿主崩溃全长这样。**看到它不要猜，先让错误透出来**
  2. 让错误透出来只需改一处：`mapFinishReason` 的 `default: return "stop"`
     改成 `kind:"error"` 时返回 `void 0`
  3. 「只有我遇到」要立刻怀疑中间层：三个不相关的上游在同一处失败 → 必然是中间件
```

**为什么记错误**：这条比任何「成功记录」都有价值——它记录的是**判断方法的问题**，而不是某个具体 bug。

---

## 小结：什么样的记录才有用

| 特征 | 说明 |
|---|---|
| **写了「为什么」** | 不只是「改了什么」 |
| **写了「已验证无效的」** | 省掉下次重复试的时间 |
| **现象 → 根因的映射** | 下次从现象能直接跳到原因 |
| **错误也记** | 错误的判断过程比正确的结论更可复用 |
| **有具体值** | 路径、命令、字节数，不是「改了一下」 |
